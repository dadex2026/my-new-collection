## Working notes for future sessions

- **Cloud sessions have no push rights.** The pattern that works: request device-bridge access to the real checkout, stage files in, edit, `SendUserFile` → `device_commit_files` back out, then hand the user exact `git add/commit/push` commands. Verify the push actually happened — this is where work has been lost three times.
- **Never run git write operations through `device_bash`.** Every object git writes there is created by the sandbox process under an owner the user's account is not on, so a single `git add` leaves a `.git/index.lock`, a `HEAD.lock`, and one `tmp_obj_*` for every object it wrote. Read-only inspection is fine with `git --no-optional-locks`. Where deletion has been granted for that folder the locks can be cleared with `rm -f`; where it has not, **not even the user's own PowerShell can delete them** — removal needs an elevated `takeown` + `icacls`. `git gc`, `git prune` and `git repack` all hit the same wall, and a `git clone` leaves the garbage behind rather than removing it, so short of the elevated route it is permanent. It is also inert: git ignores anything in `objects/` that is not a 38-character hex name.
- **`Desktop\Dashboards` is under version control as of 2026-08-28**, first commit `7216a34` — five dashboards, their prompts and their build history. 217 files / 5.8 MB tracked, from 78 MB on disk, under a `.gitignore` covering `node_modules/`, `dist/`, `build/`, `__pycache__/`, `.venv/` and editor droppings. It carries 272 undeletable `tmp_obj_*` files (2.4 MB) from that first commit, which `git fsck` and `git count-objects -v` report as *garbage found*; they were left deliberately rather than cleaned, because the elevated route was declined. **Run git in this folder from the user's own shell, not through the bridge** — deletion is granted for `TEMPLATE-OPEN-EDITION`, `TEMPLATE-TEST-LEDGER` and `my-new-collection`, but not for `Dashboards`, so every bridge-side git command there adds a fresh crop.
- **Builds don't work over the bridge** — Linux VM against Windows-installed `node_modules`, so native binaries (Rollup, esbuild) fail. `tsc --noEmit --lib es2020,dom` is a usable substitute for files with only local imports.
- **`npm` needs `--prefix frontend`** or a `cd` into `frontend/`; there is no root `package.json`.
- **More than one session may share a checkout.** Push before handing off, and check `git log` against `origin/main` before assuming the tree matches what a handoff describes.
